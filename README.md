## Curriculum

<a id="course-01"></a>
### 01. MCU 프로그래밍

> Infineon AURIX TC275에서 HAL 없이 레지스터를 직접 설정해 GPIO, 인터럽트, 타이머, ADC를 다루는 bare-metal 펌웨어를 작성했습니다.

**실습** [AURIX_TC275](AURIX_TC275) · ShieldBuddy TC275 · AURIX Development Studio

<details>
<summary><b>상세 학습 내용</b></summary>
<br>

- **디지털 입출력**: IOCR로 핀 모드를 정하고 OMR, IN 레지스터로 LED·버튼·RGB 제어, 소프트웨어 디바운스와 에지 검출
- **인터럽트와 타이머**: STM compare 인터럽트, ERU 외부 인터럽트, SRC 설정과 ISR, ISR과 main 사이 임계 구역
- **주기 실행**: 1 ms tick 기반 비선점 다중 주기 태스크, tick ISR과 main의 작업 분리, 작업별 기준 시각으로 서로 다른 주기 관리
- **실행시간과 응답성**: STM `TIM0`로 지연 루프의 실행시간 측정, 긴 대기·폴링이 다른 작업의 실행을 늦추는 영향과 짧은 ISR의 필요성
- **주기 정확성**: 다음 타이머 비교값과 작업 기준 시각에 주기를 더해 누적 오차를 줄이는 방식, 실행 시점의 흔들림(지터)과 누적 시간 오차(드리프트)의 차이
- **센서 통신**: DHT11 단선 통신, 펄스 폭 측정, checksum, 측정 상태 머신
- **아날로그**: VADC 단발·tick trigger·scan 변환, ADC 결과 인터럽트와 ring buffer, DSADC
- **신호 처리**: 이동평균, 3점 중앙값, 고정소수점 IIR 저역통과, 히스테리시스

**관련 실습** [실행시간 측정](AURIX_TC275/Lab06_stm_delay_measure.c) · [타이머 인터럽트](AURIX_TC275/Lab07_stm_isr_blink.c) · [다중 주기 태스크](AURIX_TC275/Lab09_1ms_tick_tasks.c)

</details>

### 02. 차량 통신 (CAN)

> CAN 프레임 구조와 DBC를 익히고, Kvaser 가상 CAN 채널 위에서 python-can 스크립트로 가상 ECU를 만들어 메시지를 주고받았습니다.

**실습** [python-can](python-can) · Kvaser 가상 채널 · CanKing

<details>
<summary><b>상세 학습 내용</b></summary>
<br>

- **CAN 기초**: 표준·확장 ID, DLC, 데이터·리모트 프레임, 비트레이트와 비트 타이밍(샘플 포인트)
- **DBC**: cantools로 메시지·신호 정의 읽기, 신호 인코딩, Intel·Motorola 바이트 순서
- **주기 송신**: DBC의 송신 주기 반영, 단일 루프 → 스레드 → `send_periodic()`
- **수신**: ID·마스크 필터, 수신 스레드와 송신 스레드 동시 실행


</details>

<a id="course-03"></a>
### 03. AUTOSAR

> AUTOSAR Classic의 Application, RTE, BSW 계층을 Mobilgene Studio로 구성하고, TRK-MPC5606B 보드에서 SWC와 BSW를 연결했습니다.

**실습** [AUTOSAR](AUTOSAR) · Mobilgene Studio · CodeWarrior · TRK-MPC5606B

<details>
<summary><b>상세 학습 내용</b></summary>
<br>

**기초 용어**

| 용어 | 설명 |
| --- | --- |
| Application | 차량의 기능과 제어 로직을 구현하는 응용 소프트웨어 계층 |
| SWC | 입력 처리나 제어 등 특정 기능을 담당하는 소프트웨어 컴포넌트 |
| VFB | 하드웨어 배치와 독립적으로 SWC 간 연결과 통신을 표현하는 개념 |
| RTE | SWC 간 통신과 BSW 서비스 이용을 연결하는 계층 |
| BSW | OS·통신·메모리·입출력 등 공통 기능을 제공하는 기반 소프트웨어 |

**구성요소**

| 구분 | 구성요소 |
| --- | --- |
| VFB | Component, Composition, Port, Interface, Assembly/Delegation Connector |
| RTE | Runnable, Event, Access Point |

**실습 내용**

- **OS 실습**: Task 활성화·종료, Counter와 Alarm을 이용한 주기 실행
- **RTE 실습**: Runnable 주기 실행, Sender/Receiver 데이터 전달, Client/Server 기능 호출
- **BSW 실습**
  - **입출력**: IoHwAb를 이용한 ADC·DIO·PWM 연결
  - **CAN 통신**: DBC 파일을 불러오고 COM 신호 연결
  - **메모리**: NvM을 이용한 비휘발성 데이터 읽기·쓰기와 완료 통지
- **통합 실습**: TORCS 시뮬레이터와 CAN으로 연동한 CC·LKAS SWC


</details>

### 04. 모델 기반 제어

> MATLAB/Simulink로 동적 시스템과 차량 동역학을 모델링하고, 그 위에서 ABS·크루즈·ACC 제어기와 칼만 필터를 설계한 뒤 C 코드 생성과 Arduino 배포까지 진행했습니다.

**실습** [Simulink](Simulink) · MATLAB·Simulink·Simscape · Arduino Uno

<a id="course-06"></a>
### 06. 운영체제 기초 및 실시간 스케줄링

> 운영체제가 프로그램을 실행하고 메모리를 관리하는 방식을 학습했습니다.
> bare-metal과 RTOS의 차이를 살펴보고, 작업의 주기와 마감시간에 따른 RM·EDF 스케줄링을 비교했습니다.

<details>
<summary><b>상세 학습 내용</b></summary>
<br>

- **운영체제와 실행 구조**: 프로그램 실행과 CPU·메모리·입출력 관리에서 운영체제가 맡는 역할
- **bare-metal과 RTOS의 차이**: 운영체제 없이 메인 루프·인터럽트로 작업을 실행하는 방식과, RTOS에서 태스크를 관리하는 방식 비교

| 구분 | bare-metal | RTOS |
| --- | --- | --- |
| 작업 실행 | 메인 루프와 인터럽트에서 작업 처리 | 작업을 태스크로 나누어 실행 |
| 여러 작업 관리 | 실행 순서와 주기를 코드에서 직접 관리 | 스케줄러가 태스크의 우선순위 등에 따라 실행 관리 |

- **프로세스·스레드와 문맥 전환**: 프로세스와 스레드의 차이, 실행·준비·대기 상태, 다른 작업으로 전환할 때 현재 상태를 저장했다가 다시 불러오는 과정
- **우선순위 역전**: 우선순위가 높은 작업이 낮은 작업이 사용 중인 자원 때문에 기다리는 상황과, 자원을 가진 작업의 우선순위를 일시적으로 높여 지연을 줄이는 방법
- **메모리 관리와 가상 메모리**: 프로그램이 사용하는 주소와 실제 메모리 위치의 관계, 페이지 단위 관리, 필요한 페이지를 불러오고 교체하는 과정
- **실시간 스케줄링**: 작업의 주기·마감시간·최악 실행시간, 주기가 짧은 작업을 우선하는 RM과 마감시간이 가까운 작업을 우선하는 EDF의 실행 순서 비교

</details>
